# Changelog

## Unreleased

- `Connection not saved` now sits in the Data section after `Data health`, next to the connection status, instead of in Actions between `Settings…` and `Disconnect from PDT`. Connected screens without a pulse keep it in the PDT section (#305).
- `Keychain unavailable`, the README, and the install guide no longer tell you to install a signed release, which has not shipped. The menu now reads `This PDTBar build has no Keychain access, so it can't read or remove your PDT connection`, and the docs say a copy without Keychain access never saves a sign-in and says so before you sign in ([ADR-0003](docs/adr/0003-credential-storage-and-unsaved-connections.md), #305).
- Fixed a connection change the Keychain refused growing by one held event per token refresh, about one an hour, when another PDTBar process had stored the pair: once a read shows what the Keychain holds, the held refreshes fold into one, so the held change stays the same size however long the Keychain refuses it (#305).
- A menu taller than the screen no longer scrolls Settings, Disconnect, and Quit out of reach: only when it would overflow, PDTBar folds rows into submenus in a fixed order (Big movers, then the income list, then the allocation chart, then attention items spilled into Allocation, and as a last resort one row per section) until it fits, and every folded row stays one click away. Menus that fit render exactly as before; the tallest fixture menu now measures 777 pt on a 876 pt screen and 901 pt on a 919 pt screen instead of 1071 pt, and 842 pt and 890 pt instead of 1184 pt after a failed refresh (#296).
- `menu-measure` now warns when macOS clamped the captured menu to the screen, and its report adds `contentHeight` and `clampedToScreen`; before, a clamped menu reported the clamp (1123 pt on a 1130 pt screen) as the menu height (#296).
- A build that can't save your sign-in, such as a local build without the keychain access entitlement, now says so on the `Not connected` screen before you sign in and after every relaunch: `This PDTBar build can't save your sign-in. You'll sign in each time PDTBar starts`. `Sign in with PDT` and `Use a PDT token…` stay. PDTBar reads this from its own code signature and makes no Keychain call for it (#301).
- A sign-in or pasted token the Keychain refuses to save, as on a local build without the keychain access entitlement, now keeps PDTBar connected until it quits: the portfolio loads as usual, and every connected menu shows one `Connection not saved` row from the moment sign-in returns. A refreshed token pair the Keychain refuses is used the same way. PDTBar keeps trying to save and drops the row once the Keychain accepts. After a quit such a build starts as `Not connected` again ([ADR-0003](docs/adr/0003-credential-storage-and-unsaved-connections.md) decision 3, signed off by Bram).
- Fixed `Check again` signing you out after a sign-in the Keychain refused to save, as on a local build without the keychain access entitlement: PDTBar dropped the sign-in, showed `Keychain unavailable`, and the next check read `Not connected`. PDTBar now holds a sign-in or pasted token the Keychain refuses and saves it once the Keychain accepts it. A refreshed token pair, a rejection from PDT, and a disconnect the Keychain refuses are held the same way, so only PDT or `Disconnect from PDT` ends a connection (#301).
- Big movers now signs the move the way Pulse does (`+12.4% over recent window`), so a rise no longer reads like an unsigned change.
- The portfolio summary no longer shows `Unavailable` when PDT returns only one of CAGR and Total increase: the figure PDT has fills the row by itself (#294).
- PDT sync failures now name themselves outside Data health too: a failed first fetch says which failure stopped it and what to do (`PDT rate limit; try again in 2 min`, `Could not reach PDT; check your connection`, `PDT server problem; try again later`) instead of a fixed message; a token that stops working, missing read access, or a paused subscription during a background refresh's later steps now moves the menu to `Reconnect to PDT` or `PDT access paused` over the freshly saved pulse instead of `Details partially filled` with PDT still shown as connected; and a refresh whose holdings request PDT rejected keeps its failure on the reconnect and paused screens and through `Check again`, so `Copy diagnostics` still copies the trace id there (#191).
- Data health now names why it needs attention instead of `Needs attention`: the summary reads the first cause (for example `2 stale prices`, `Showing a saved copy`, `Reconnect needed`, `Detail fill failed`), and every cause maps to the row that shows it. A detail fill that completed before the latest sync now reads `Incomplete; last complete <date>` instead of `Completed <date>` (#293).
- Added `make smoke-menu` (`Scripts/verify_pdtbar.sh menu-smoke`), a local real-menu smoke: it builds PDTBar, launches the `concentration-pressure` fixture, opens the real menu through Accessibility, checks the Summary, Pulse, Allocation overview, Income, Big movers, Data (freshness), Data health, and Actions selectors, opens the `Detailed info` and `Data health` submenus, and saves PNGs that show only PDTBar's own status item and menus. It fails instead of skipping when it cannot drive or capture the menu; CI runs a test that keeps its selector list matched to the rendered menu (#147).
- Fixed a background refresh cancelled before its first step, as quitting does, leaving the previous refresh's failure readable as if this run had failed; the stored failure is now cleared first. Added regression tests and a model property that a slow or failed first X-ray or income page keeps the saved X-ray and Income, which the REST client already did (#275).
- Redesigned the public site: top navigation, a home page hero that shows the real open menu with labelled callouts, numbered sections, a contents list on the install and features pages, and light and dark themes that follow the system setting until you pick one. The site now declares Dutch as its default language, with English under `/en/`, and the page copy in both languages was edited for plain wording.
- Removed the Claude CLI and PDT MCP code the app no longer used: the legacy connector with its process handling, parsers, and retry policy, the manual Claude and live mcporter smokes, and the pinned mcporter `package.json`; nothing falls back to them. Added `make smoke-api`, which runs the scripted API client, snapshot, sign-in, first-fetch, and returning-launch smokes in one sandbox that kills any non-loopback connection, DNS lookup, Keychain lookup, or `claude`, `codex`, or `mcporter` exec, and recorded provenance for the synthetic REST fixtures (#250).
- Data health now describes PDT access instead of Claude and PDT MCP readiness: separate Source, Access, Cache (last sync and last complete sync), Prices, Detail fill, and Diagnostics rows; a saved copy is never shown as healthy or freshly fetched; a failed sync says what to do (reconnect, renew your subscription, try again in N min after a rate limit, check your connection, try again later); and `Copy diagnostics` holds only the step, endpoint, failure category, request count, and PDT's trace id, never a token, account id, URL, or response text. A rate limit that outlasts PDTBar's own retries now ends that refresh instead of asking PDT again for each remaining detail (#249).
- Switched launch and the menu to the PDT connection: `Sign in with PDT` in the browser or `Use a PDT token…`, then a read-only first fetch that saves before it shows the pulse. The menu now names each connection state (not connected, signing in, reconnect with the reason, PDT access paused, Keychain unavailable), keeps the last pulse visible when PDT stops accepting the connection, and offers `Check again` and `Disconnect from PDT`. Claude login, Claude CLI checks, and PDT MCP setup are gone from launch and the menu (#248).
- Release builds sign a keychain access group from a Developer ID provisioning profile; a build without it shows `Keychain unavailable` instead of using the login keychain (#248).
- Added the PDT sign-in layer behind the REST path, not yet in the app: browser sign-in with PKCE and a `127.0.0.1:47245` callback that ignores requests without its `state`, token refresh that is single-flight across PDTBar processes through a store lock, stores the rotated pair before use, keeps a pair the store refused until it is stored or replaced, and backs off after a refresh that got no answer, a pasted read-only token fallback, Keychain and dev file stores, disconnect, and `pdtbar-dev pdt-*` commands for live proof (#245).
- Fixed a Claude/PDT setup outage seen while fetching price history still starting the performance phase, which spent one more doomed Claude CLI run (up to its timeout) before the refresh degraded; an outage seen in any background detail phase now skips every later phase (#272).
- Fixed a returning concentration alert staying hidden after PDTBar quit during a background refresh; the old read mark is now cleared before the snapshot that records the holding crossing back above the threshold is saved (#270).
- Fixed "Log in with Claude" leaving helper processes from `claude auth login` running after the attempt ended, whether it succeeded, failed, timed out or was cancelled; every Claude CLI run now ends its whole process group, so `claude auth status`, `claude -p` and `claude mcp list` helpers no longer outlive their run either (#271).
- Fixed marking a pulse row read during a background refresh: the refresh progress rows kept stopping and "Refresh now" came back while the refresh still ran, and the row turned unread again when the refresh finished. Marking a row read now changes only the pulse rows, and every published pulse reads the current read state (#268, #269).
- Fixed "Refresh now" starting a portfolio refresh while PDTBar was still checking Claude setup on a returning launch, which let a setup screen cover a running refresh and could leave "Checking Claude setup" up with no check running; the row now waits for the check, and marking a row read during the check keeps it (#267).
- Fixed launch staying on "Checking Claude" forever when you log in with Claude during the first readiness check and an older check's result overwrote the newer one waiting for the cached pulse (#274).
- Added a background detail refresh over the read-only PDT REST API that commits once at the end, keeps last-good facets on optional failures, and skips later phases after an auth outage; the shipped refresh stays on Claude until PDT sign-in lands.
- Fixed portfolio-value privacy masking so money-bearing menu fields render from typed values instead of relying on currency regexes and prose-specific scrubbing.
- Stopped in-flight Claude process trees when background detail refreshes time out or PDTBar quits, with a bounded worker shutdown grace.
- Declined to annualize portfolio returns over periods shorter than 90 days and now explains when the reporting period is too short.
- Fixed invalid PDT income pagination sizes that caused deterministic server rejections and unnecessary Claude CLI retries.
- Prevented background detail retries from multiplying Claude CLI runs, added phase deadlines, and made Data Health report the true run count.
- Bounded PDT list pagination with empty-page termination, 50-page caps, phase deadlines, and Data Health diagnostics for partial results.
- Removed the fixed one-second delay and repeated Claude project scans from inline PDT reads while preserving file-delivered result handling and cleanup.
- Fixed first portfolio fetches discarding completed holdings when an optional PDT facet fails.
- Fixed optional PDT performance reads timing out below observed production latency, which left CAGR and total increase permanently unavailable.
- Fixed a blank allocation-chart panel remaining visible after opening and closing Settings.
- Added a native Settings window with a `Show portfolio values` checkbox that hides displayed monetary portfolio values without deleting cached local data.
- Added a compact portfolio summary above the overview with total value, inception-to-latest total increase, and CAGR annualized from PDT's selected full-period return.
